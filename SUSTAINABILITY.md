# Sustainability Model

## Purpose

The BOSC Community Library needs a realistic sustainability plan because open source projects can fail when there is no time, money, or responsibility for maintenance. Since this project is designed for education and public use, the main goal is to keep the core library free while still finding ways to support hosting, review, documentation, and training.

## Red Hat Service-Based Model

The Red Hat model is based on making the core software open source, then earning money from services around it. For BOSC Community Library, this could work through teacher training, school deployment support, local hosting, offline copies, resource curation, and technical support. For example, a school or district could use the library freely, but pay for help setting it up, organizing resources by subject, or training staff to contribute.

I think this model is practical because many institutions do not only need software. They need people who can install, explain, maintain, and support it. The risk is that maintainers may begin to focus only on paying clients and ignore ordinary community users.

## Foundation-Driven Model

A foundation-driven model would place the project under a neutral group made up of educators, software students, lecturers, community contributors, and possibly public-sector representatives. Funding could come from grants, university support, donations, and partnerships with education organizations.

This model feels suitable for a community library because it protects trust. No single company controls the project direction. It also fits the academic environment because universities like Bugema can support research, student contribution, and review of resources. The weakness is that grants and donations are not always stable, so the project may struggle if there is no active leadership.

## Recommended Approach

The best approach for BOSC Community Library is a hybrid model. The core repository should remain community-governed and open. Paid services can support practical needs like training, hosting, and implementation, but they should not control the main project roadmap.

Possible funding sources include:

- Training workshops for teachers and school ICT staff.
- Small support contracts for schools or districts.
- Grants from education and digital inclusion programs.
- University-based student contribution programs.
- Partnerships with libraries, NGOs, and education departments.

## Accountability

To keep the project trustworthy, all major decisions should be visible through GitHub issues, pull requests, and public documentation. Funding should not allow one sponsor to quietly control the resource list. The Apache 2.0 license should remain in place so that the public can continue using the project even if a service provider leaves.
