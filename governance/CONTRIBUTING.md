# Contributing To BOSC Community Library

Thank you for helping improve the BOSC Community Library. Contributions should strengthen the accuracy, accessibility, legal clarity, or public usefulness of the resource catalogue.

## Ways To Contribute

- Add verified open educational resources.
- Fix broken links or inaccurate metadata.
- Improve category organization.
- Add local language support.
- Improve documentation and governance files.
- Review pull requests and leave clear feedback.

## Development Workflow

1. Check existing issues before starting work.
2. Comment on the issue you want to handle.
3. Create a dedicated branch from `main`.
4. Make focused commits with clear messages.
5. Open a pull request and link the related issue.
6. Request review and address feedback.
7. Merge only after the checklist is complete.

## Branch Naming

Use short branch names that describe the purpose:

- `fix/broken-resource-links`
- `feat/local-language-support`
- `feat/searchable-resource-database`
- `refactor/category-structure`
- `docs/government-proposal`

## Commit Style

Use conventional-style messages where possible:

- `docs: expand legal analysis`
- `feat: add local language resources`
- `fix: repair broken resource links`
- `refactor: reorganize category files`

## Resource Quality Rules

Every resource entry should include:

- Title
- Category
- Provider or publisher
- URL or access location
- License or reuse condition
- Target audience
- Connectivity requirement
- Short description

Do not add resources with unclear copyright status. If the license is unknown, mark the entry for review instead of presenting it as reusable.

## Pull Request Review

Each pull request should include:

- A link to the issue it resolves.
- A summary of changes.
- Evidence that links or data were checked.
- A peer review comment before merge.

For the exam workflow, each of the five required issues must have its own branch, pull request, review comment, and merge record.
