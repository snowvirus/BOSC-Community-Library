# Exam Work Plan

Use this plan to avoid a single-day bulk upload. The exact dates can be adjusted, but the important point is that GitHub should show steady activity across the exam period.

## Day 1: Repository Architecture

- Add README, license, Code of Conduct, contribution guide, and GitHub templates.
- Commit with a message such as `docs: establish open source project structure`.
- Push to GitHub.

## Day 2: Legal And Baseline Resources

- Expand `LEGAL_ANALYSIS.md`.
- Add the first resource categories and database file.
- Open Issue #1 for broken or incomplete resource metadata.
- Create branch `fix/category-metadata`.
- Merge after review.

## Day 3: Functional Bug Fix

- Open Issue #2 for broken link checks or missing resource access notes.
- Create branch `fix/resource-link-validation`.
- Fix the resource entries.
- Open a pull request, add review evidence, and merge.

## Day 4: Feature Enhancement

- Open Issue #3 for local language support.
- Create branch `feat/local-language-support`.
- Add local language category content and database entries.
- Open a pull request, add review evidence, and merge.

## Day 5: Feature Enhancement

- Open Issue #4 for a searchable resource database.
- Create branch `feat/searchable-resource-database`.
- Improve the CSV index or add search instructions.
- Open a pull request, add review evidence, and merge.

## Day 6: Refactoring And Sustainability

- Open Issue #5 for resource organization refactoring.
- Create branch `refactor/resource-organization`.
- Improve folder structure and documentation links.
- Add or finalize `SUSTAINABILITY.md`.
- Open a pull request, add review evidence, and merge.

## Day 7: Submission Audit

- Finalize the Ministry proposal and reflective journal.
- Add screenshots to `docs/SUBMISSION_LOG.md`.
- Confirm all five issues and PRs are closed.
- Submit the GitHub repository URL and audit evidence.

## Important

Do not fake GitHub activity. Create the issues, branches, pull requests, reviews, and merges as real GitHub actions. Screenshots should come from the actual repository.
